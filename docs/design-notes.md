# 设计说明 — 稿纸 2.0

一个桌面待办清单。设计代号仍是「稿纸」，但第二版把皮肤换掉了：**骨架留，纸味去掉。**

## 一、为什么改

第一版是「把红格稿纸当成一台精密仪器」：生宣底、方格纸纹、贯穿全高的页边线、
思源宋体写正文、Bahnschrift 写仪器小字、朱砂只给删除。

功能没问题，但界面读起来是**纸本文具**，不是这个时代的桌面应用：衬线正文偏"印刷品"，
方格底纹偏"拟物"，一条深色竖线贯穿到底偏"账本"。所以第二版保留真正有用的东西，
换掉只是风格的东西：

| 保留 | 换掉 |
| --- | --- |
| 左栏放状态、右栏放内容的结构 | 方格纸底纹（整块去掉） |
| 完成 = 一道划过去的笔迹 | 贯穿全高的页边线（改成当前行左边的一小段竖条） |
| 靛墨作为唯一强调色 | 思源宋体正文 → Segoe UI Variable + Noto Sans SC |
| 动效只回答动作 | Bahnschrift 仪器小字 → 同一个无衬线家族，靠字重拉层级 |
| 朱砂只给删除 | 生宣底 → 干净的白与近白表面 |

## 二、设计主张

**「界面是黑白的，唯一的颜色是你花掉的墨。」**

完成一件事，是这份清单里唯一值得上色的事件：方框填满靛蓝、白勾被描出来、
一道靛蓝的笔迹划过文字。除此之外整个界面只有黑、白、灰。
颜色因此不再需要装饰性——它出现的地方一定意味着状态变了。

配色的三个角色：
- **面**：`--bg` 近白、`--raise` 纯白（输入框、选中行、设置里的分段控件）
- **墨**：`--ink` → `--ink-3` 四级灰，承担全部层级
- **信号**：`--accent` 靛蓝（只用于完成、当前行、主操作链接）、`--seal` 红（只用于删除）

## 三、Token 系统

### 色

| 名称 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `bg` | `#FAFAFB` | `#0F1114` | 面板底 |
| `raise` | `#FFFFFF` | `#17191D` | 抬起来的面：输入框、选中行 |
| `hover` | `#F1F2F5` | `#1E2127` | 悬停行、分段控件底 |
| `ink` | `#0F1319` | `#E9EBEF` | 正文、标题 |
| `ink-2` | `#565E6B` | `#A2A9B4` | 次要信息、设置里的说明 |
| `ink-3` | `#7B8492` | `#7D8590` | 提示、日期、已完成事项 |
| `line` | `#E8EAEE` | `#23262C` | 发丝分隔线 |
| `line-strong` | `#D9DCE3` | `#31353D` | 输入框边框、开关轨道 |
| `mark-line` | `#BCC2CC` | `#3D434C` | 未完成方框的描边 |
| `accent` | `#2E56E0` | `#7C93FF` | 完成、当前行、主操作 |
| `seal` | `#E5484D` | `#FF6369` | 删除 |

对比度：正文 `ink` 对 `bg` 约 17:1，`ink-2` 约 6.3:1（说明文字也过 AA），
`ink-3` 约 4.2:1（只用于辅助信息）。

### 字

一个家族，不靠换字体拉层级，靠**字重与字号**：

```css
--font-ui: "Segoe UI Variable Text", "Segoe UI Variable", "Segoe UI",
           "Noto Sans SC", "Microsoft YaHei UI", system-ui, sans-serif;
```

Segoe UI Variable 是 Windows 11 的可变字体，拉丁字母和数字用它，汉字落到思源黑体
（Noto Sans SC）。数字一律 `font-variant-numeric: tabular-nums`，所以计数变化时不会左右跳。

| 角色 | 字号 / 字重 |
| --- | --- |
| 召唤行 | 16px / 400，字距 -0.01em |
| 待办正文 | 15px / 400，行高 1.5 |
| 日期（顶部标题） | 13px / 600 |
| 设置项标题 | 14px / 500 |
| 说明、分段控件、按钮 | 12px |
| 图例、分组标签 | 11.5px |

行宽上限约 34 个汉字。

### 版面

```
     ┌────────────────────────────────────────────┐
     │  10月11日 周日                   还有 3 件  ⚙ │  46px：日期 13/600，计数 12 灰
     │ ┌────────────────────────────────────────┐ │
     │ │ ＋   记一件要做的事…                    │ │  46px：白底圆角输入框，发丝边框
     │ └────────────────────────────────────────┘ │
     │  ▏☐  写设计说明                          × │  ← 当前行：白底 + 极轻投影 + 左侧靛蓝竖条
     │   ☐  修一个登录的 bug                      │
     │   ☐  读《技术的本质》第三章                 │
     │                                            │
     │   已完成 1                          清除   │  分组标签 + 就地操作
     │   ☑  ~~买牛奶~~                            │  方框填满靛蓝，白勾，靛蓝笔迹划过
     │                                            │
     ├────────────────────────────────────────────┤
     │                        回车 记下  ↑↓ 选择  ESC 收起 │  36px 图例
     └────────────────────────────────────────────┘
```

行是圆角药丸（10px），左右各留 8px 内缩，悬停铺 `hover`，选中是白底加一层很轻的投影、
左侧一段 3px 的靛蓝竖条——那道贯穿全高的页边线，缩到只剩「你在这里」。

对齐：全部左对齐，方框列固定 26px，正文起点在面板左侧 52px 处（空列表的提示文字也对齐这条线）。

### 原则

1. **颜色是信息，不是装饰。** 靛蓝出现 = 状态变了；红出现 = 要删东西了。
2. **一个家族，靠字重分声部。** 不用第二种字体来假装层级。
3. **深度只用两层。** 面板一层投影，抬起的面一层发丝边 + 极轻投影，没有第三种。
4. **圆角有层级。** 面板 16px、输入框 12px、行 10px、方框 5px——从大到小，不是处处一样。
5. **动效只回答动作。** 全应用只有三处：面板被召唤、任务被划掉、任务沉到已完成区。
6. **不装饰空处。** 清单短的时候，下半屏就是空的，不放插画、不放鼓励语。

## 四、对照「AI 默认套路」自检

| 套路 | 本设计 | 结论 |
| --- | --- | --- |
| 暖奶油底 + 高对比衬线标题 + 陶土色 #D97757 | 近白冷灰底 + 无衬线；强调色是靛蓝 | 避开 |
| 近黑底 + 单一荧光绿／朱红 | 深色模式是 `#0F1114` 配浅靛蓝，不是荧光色 | 避开 |
| 报纸式细线 + 零圆角 + 密集多栏 | 单列药丸列表，圆角有明确层级 | 避开 |
| SaaS 卡片套件（同样圆角 + 同样柔和阴影 + 渐变装饰） | 没有卡片、没有渐变装饰；投影只出现在「抬起来的面」 | 避开 |
| 模板件：全大写 eyebrow、`·` 连元信息、`→` 结尾按钮、等宽体小标签 | 中文界面；没有 eyebrow；分隔用留白；数字用可变字体不是等宽体 | 避开 |
| 大数字 + 小标签 + 渐变强调 | 计数是 12px 的小字，放在标题行右端 | 避开 |

## 五、图标

一块靛蓝圆角方块（圆角 21.9%，Windows 11 图标量级）+ 一个白色的勾，没有第二个记号。

第一版图标是「稿纸 + 朱砂页边线 + 靛墨勾」两个记号。它的问题不是画得不好，而是**被约束逼到了死角**：
勾必须完全落在页边线右侧（≥26% 处），又要占满 55% 的宽度，于是宽高比被压到 1.64 左右，
而真正的勾（对照 Segoe / Arial 的 U+2713）宽高比是 0.80–0.94。flat 成一道「弯钩」，
32px 时容易被读成字母 L 或一撇。加上纸与朱砂在新界面里已经不存在了，
所以换成一个记号、一个颜色——识别问题也随之消失。

生成脚本 `design/make-icon.py`，由 `pnpm tauri icon` 铺开成整套尺寸（32 → 256px，含 .ico / .icns）。
新图标 32px 时的实测量：勾横跨 57.6%（18.4px），笔画 4.7px，光学中心在 48.3%。

## 六、功能范围

- 全局快捷键召唤／收起（默认 `Ctrl+Alt+Space`，设置里按键录入即可换绑；注册失败会明说）
- 无边框圆角面板 440×678（内容 400×628，四周留出阴影的位置），置顶，失焦自动收起（可关），
  ESC 收起，顶部一行可拖动，记住窗口位置
- 记下 → 回车；`↑↓` 选择；`空格` 完成；`E`/双击 编辑；`Alt+↑↓` 排序；`Delete` 删除；`Ctrl+Z` 撤销
- 已完成沉底并归入「已完成 N」分组，可就地清除；数据落盘（原子写 JSON）
- 托盘：显示／隐藏、退出；左键单击托盘图标切换面板；重复启动只唤出已有窗口
- 浅色／深色／跟随系统

## 七、走查记录

用真实渲染的截图逐条核对（440×678 @2x），修掉的问题：

1. **召唤行永远有焦点**，于是 `:focus-visible` 给它套了一圈 2px 描边——主角变成了「带边框的输入框」。
   改成：不套焦点框，靠光标、靛蓝的加号、边框由 `line` 变 `line-strong` 来说「你在这里」。
2. **`ink-3` 只有 2.8:1**，提示文字太浅。整体上调到 4.2:1，设置里的说明文字改用 `ink-2`（6.3:1）。
3. **方向键选中某一行之后，焦点仍留在召唤行里**，于是空格被当成打字而不是「完成」。
   这是键盘模型的真 bug，靠真实按键才试出来；选中行时必须让召唤行失焦。
4. **「已完成不留在此列表」时**，选中的那一行会消失但选中状态还在，底部图例在说一个看不见的项。
   补了守卫：选中项不在可见列表里就把光标还给召唤行。
5. **设置页的入场动画**（keyframes + `both`）在无头渲染里冻在了半透明状态。它本来就只是装饰，
   删掉之后设置页硬切，符合「动效只回答动作」。
6. 第二版走查又量出两处：空列表的提示文字比正文起点**右了 8px**；未完成方框的描边
   （`line-strong`）在白底上**太淡**。各加一个对齐值与一个 `mark-line` token 修掉。

## 八、真机验收

打包后的 release 可执行文件在真实 Windows 桌面上跑过：

- **首次启动**面板自己亮出来。这靠 `window::SHOW_GRACE`（刚显示 1.2 秒内的失焦不算用户走开）保住：
  把应用拉起来的那个窗口会把焦点抢回去，没有这个宽限期，用户双击图标后什么也看不到。
- **全局快捷键 `Ctrl+Alt+Space`** 连按三次：显示 → 收起 → 显示，三次都对。
- **落盘**：带一条待办的 `data.json` 进去，应用读到、界面渲染、前端再原样写回——
  `load_data` / `save_data` 这条 JS ↔ Rust 的往返是通的。
- **损坏数据**：故意写坏文件，应用按设计改名成 `data.corrupt-<时间戳>.json` 后从默认值启动。
  顺带发现部分 Windows 编辑器会写 UTF-8 BOM，而 serde 会因此判定文件损坏——
  已加剥离 BOM 的处理，不能因为一个 BOM 就把用户的待办丢掉。
- **exe 里嵌的图标**：从二进制里抽出来核对过。
- **最终二进制跑的就是新版界面**：用单实例那条路径让常驻实例把面板显示出来（不注入任何按键），
  截图确认渲染的是第二版界面，并且用户的 4 条真实待办正常加载。
- stderr 全程只有一行「未恢复窗口位置，使用默认居中」（没有 `window.json` 时是预期的）。
  反过来说，快捷键注册、托盘创建、窗口置顶这几条路径都没有报错。

**打包时踩到的一个坑**（已写进 README）：cargo 盯的是 Rust 源码的 mtime，
换了图标之后 `cargo build` / `tauri build` 都可能认为无事可做，于是 exe 里仍是旧图标——
我核对时发现过，靠 `cargo clean -p todolist --release` 才真正换过来。
所以验收 binary 时**不能只看构建命令成功**，要把资源抽出来看。

没有做到真机验收的部分，如实记在这里：托盘菜单点击、窗口位置记忆（要拖动窗口）、
设置里的换绑快捷键／开机自启／打开数据文件夹这几个命令，以及面板内的键盘输入
（这部分是在真实渲染的浏览器里逐条按过的，同一套组件与样式）。
